# Templates

The single source of truth for how every article in this knowledge base is structured. All entries follow [`article-template.md`](article-template.md); the section order is fixed so readers and reviewers always know what to expect. This guide explains the frontmatter, how each section serves the project's goals, and the rules that keep articles consistent, discoverable, and durable.

> The template is the copyable shape; the [`standards/`](../standards/README.md) directory is the specification behind it — the [article quality standard](../standards/article-quality.md) defines each section's acceptance criteria, and [`metadata-schema.md`](../standards/metadata-schema.md) is the authoritative frontmatter reference.

## Files

- [`article-template.md`](article-template.md) — the standard article template. Copy it, rename it to the kebab-case form of the title, and fill in every section.

## How to start a new article

1. Find the article's home in the [Knowledge Map](../KNOWLEDGE_MAP.md) and confirm its row in the [Article Inventory](../ARTICLE_INVENTORY.md).
2. Copy `article-template.md` into `docs/<part>/<domain>/` and rename it to `<slug>.md`.
3. Fill in the frontmatter and every section. Do not delete sections — if one does not apply, keep the heading and write one line saying why.
4. Add or update the article's node in the domain's `graph.json`, mirroring the frontmatter (`prerequisites`, `related`, `next`, `alternatives`, `common_mistakes`), and adjust counts in [GRAPH.md](../GRAPH.md) if the article is new.
5. Run `python3 scripts/build-links.py` (refreshes the inverse `next` edges), then `python3 scripts/validate-links.py` — it must pass. Regenerate the reader views with `scripts/build-links-matrix.py` if you changed relations. See [`INTERNAL_LINKING.md`](../INTERNAL_LINKING.md) for the model.
6. Self-review against the checklist in [CONTRIBUTING.md](../CONTRIBUTING.md) and open a pull request.

## Frontmatter reference

The YAML block at the top is machine-readable metadata. It powers search, drives the reading graph, and must stay in sync with the domain's `graph.json`.

| Field | Required | Purpose |
| --- | --- | --- |
| `title` | yes | Human-readable Title Case. Matches the H1 and the `graph.json` title. |
| `slug` | yes | Kebab-case file name (without `.md`). Stable — never changes once published. |
| `description` | yes | 150–160 char meta description. SEO snippet and social preview. Lead with the primary keyword. |
| `keywords` | yes | Search terms and synonyms a reader would use to find this. |
| `part` | yes | The numbered Part, e.g. `03 · Application Architecture`. |
| `domain` | yes | The domain folder's display name (the article's Category). |
| `subcategory` | yes | The Topic group from the domain README. |
| `difficulty` | yes | `Foundational` \| `Intermediate` \| `Advanced` \| `Staff`. |
| `reading_time_min` | yes | Estimated minutes; matches `graph.json`. |
| `priority` | yes | Inherited from the Part (`Critical` \| `High` \| `Medium`). |
| `status` | yes | `Planned` \| `Draft` \| `In Review` \| `Published`. |
| `canonical` | yes | `true` if this file is the concept's one canonical home. |
| `last_reviewed` | yes | ISO date of the last accuracy review, for durability tracking. |
| `prerequisites` | yes | Read BEFORE this. Article titles; cross-domain as `Article · Domain`. |
| `related` | yes | Closely connected article titles (see-also, undirected). |
| `next` | yes | Read AFTER this — the inverse of another article's prerequisites (≤5). Regenerated by `scripts/build-links.py`. |
| `alternatives` | yes | Substitutes: other approaches to the same problem. `[]` if none. |
| `common_mistakes` | yes | Links into the anti-pattern catalog (`anti-patterns/README.md#<domain>`) plus this article's own `#common-mistakes` section. |
| `frameworks` | yes | Frameworks the article assumes; `[]` if agnostic. Name versions when behavior depends on them. |
| `og_image` | no | Path under `assets/` for the social/OG image. |

## The section model, and the goal each section serves

Every section earns its place by advancing at least one of the project's eight goals.

| Section | Primary goal(s) it serves |
| --- | --- |
| **TL;DR** + `Recommendation` | Learning (payoff first), SEO (answer-first snippet) |
| **At a Glance** table | Readability (scan in seconds), Trade-off thinking |
| **Prerequisites** | Learning (dependency chain), Internal linking |
| **Overview** | Learning, SEO (keyword in first 100 words) |
| **The Problem** | Learning, Practical engineering |
| **Why It Matters** | Learning (motivation) |
| **How It Works** | Learning (mental model), Practical engineering |
| **When To Use / When NOT To Use** | Trade-off thinking, Practical engineering |
| **Common Mistakes** (symptom → why it fails → fix) — the `common_mistakes` relation | Anti-pattern detection, Internal linking to `anti-patterns/` |
| **Bad Example** | Anti-pattern detection, Production examples |
| **Good Example** | Production examples, Practical engineering |
| **Trade-offs** (+ table) | Trade-off thinking |
| **Alternative Approaches** — the `alternatives` relation | Trade-off thinking, Internal linking |
| **Production Notes** | Practical engineering, Production examples |
| **Real-World Usage** | Production examples |
| **Checklist** | Practical engineering, Readability |
| **FAQ** | SEO (featured snippets), Learning |
| **Next Articles** — the `next` relation | Internal linking, Learning paths |
| **Related Articles** — the `related` relation | Internal linking, Learning paths |
| **References** | Durability, Learning |

## Goal-by-goal: how the template maximizes each

**Learning.** The article front-loads the payoff (TL;DR + recommendation), then builds from problem → why → mental model → practice, so a reader can stop at any depth and still have gained something. Prerequisites and Related Articles turn a single page into a path.

**SEO.** One H1, descriptive question-shaped H2s, a keyword-leading `description`, a `keywords` list, an FAQ that targets real queries, and an answer-first TL;DR. Images carry descriptive alt text; the `og_image` field feeds social previews.

**Readability.** An At-a-Glance table and TL;DR give a two-second overview; prose (not slides) carries the reasoning; tables and a checklist handle anything that scans better as a grid. Fixed section order means readers learn the shape once.

**Internal linking.** Every article carries five typed relations — Prerequisites (before), Next Articles (after), Related Articles (alongside), Alternative Approaches (instead), and Common Mistakes (into the anti-pattern catalog) — all linking canonical homes and using `Article · Domain` for cross-domain references. The template enforces "link the canonical home, never re-explain," which keeps the [dependency graph](../GRAPH.md) accurate and acyclic. The full model, invariants, and generation pipeline are in [`INTERNAL_LINKING.md`](../INTERNAL_LINKING.md).

**Practical engineering.** How It Works, Production Notes (observability, testing, rollout, security, a11y), and the Checklist move the article from theory to something a team can ship and operate.

**Trade-off thinking.** Trade-offs (advantages *and* disadvantages, plus a cost table) and Alternatives & Comparisons force an honest decision: the recommendation must follow from the stated costs, and every alternative names when it wins.

**Anti-pattern detection.** A dedicated Common Mistakes section names the smells in symptom → why-it-fails → fix form, links the domain's entry in the shared [`anti-patterns/`](../anti-patterns/README.md) catalog, and the Bad Example shows one in realistic code — so reviewers can catch them, not just admire the good version.

**Production examples.** Bad and Good examples must be realistic and runnable, with real error handling, edge cases, cancellation, and cleanup — reinforced by Real-World Usage and Production Notes so the example reflects how the pattern actually lives in a system.

## Non-negotiables

- Exactly one H1, matching `title`.
- Fill every section; never delete one. A non-applicable section keeps its heading and gets a one-line reason.
- Both code examples are realistic and runnable, each fence language-tagged.
- Every cross-reference is a real link to the canonical home; cross-domain prose uses `Article · Domain`.
- Frontmatter and `graph.json` stay identical for the shared fields.
- US English, prose over slides, one topic per file.
